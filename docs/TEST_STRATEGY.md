# 测试策略与验收矩阵

> 本文档是当前规则验证、TDD 顺序和发布测试门禁的权威真源。旧测试计划若与本文或 `GAME_RULES.md` 冲突，仅作为历史记录。规则期望以 `GAME_RULES.md` 为准，测试不得反向定义另一套规则。

## 1. 目标

测试必须证明以下结论，而不只是获得覆盖率数字：

- 本地双人、AI、LAN 与在线服务端遵守同一套确定性规则契约。
- 横纵双吃、终局优先级、50 ply 和 60 秒边界正确。
- 随机先手、复局交替、撤销重做、存档回放不会破坏规则状态。
- LAN 和在线对局在重复、乱序、断线和重连条件下仍以权威端状态为准。
- 一局完成后，存档清理、最近 20 局归档和统计只执行一次。
- 语音和冥想交互不泄露识别原文，且只生成由同一权威规则链处理的落子意图。

## 2. 测试分层

1. **纯 Dart 单元测试**：覆盖吃子、合法移动、状态转移、终局优先级、计时边界、序列化和统计聚合。规则层测试不得依赖 Flutter、真实时钟、随机源、文件系统或网络。
2. **BLoC 测试**：验证用户事件、AI 回合、生命周期、自动存档和错误/等待状态的转换。
3. **协议契约测试**：验证 LAN 与在线消息版本、完整吃子列表、修订号、去重、拒绝和全量状态往返。
4. **Widget 测试**：验证当前行棋方、倒计时、双吃反馈、终局原因、继续游戏和历史回放入口。
5. **集成测试**：验证完整离线对局、应用暂停/恢复、双端 LAN、断线重连和持久化闭环。
6. **真机验收**：覆盖 Android 前后台、锁屏、局域网切换、进程重启和 Google Play 内部测试包。
7. **服务端测试**：使用纯 TypeScript 规则、假时钟和 Socket 假实现验证服务端权威规则、身份绑定、指令幂等、60 秒超时、断线重连和协议输入边界；数据库与真实 Socket 留给本地集成和 staging 验证。

每个切片按“失败测试 → 最小实现 → 重构 → 上层接入 → 回归”的顺序完成。不得先在 UI 或 LAN 层临时复制规则。

## 4. 规则场景明细

### 4.1 吃子

- 对横行和纵列分别参数化测试 `1-1-0-E`、`E-1-1-0`、`E-0-1-1`、`0-1-1-E`。
- 每种排列都覆盖移动棋子位于相邻双子的第一枚和第二枚。
- 覆盖 0、1、2 枚吃子结果，并验证返回顺序固定为横向后纵向。
- 覆盖棋盘四边和四角，确保完整 4 格轴线判定没有越界或短线误判。
- 覆盖移动前已存在合法外形但移动子不在其中，以及对方移动后暴露外形，两者均不得被动吃子。
- 验证移动记录、JSON、存档、回放和 LAN 契约都保留完整吃子列表。

### 4.2 终局优先级

- 超时边界到达时，即使队列中已有合法落子，也先判当前方负且棋盘不变化。
- 同一步既把对方降至 1 子又达到 50 个未吃 ply 时，以棋子数胜结束。
- 第 50 个 ply 没有吃子且切换后对方无路可走时，以和棋结束。
- 一步发生任意吃子，包括双吃，连续未吃计数都归零。
- 已结束快照、棋子数小于或等于 1 的载入快照、无合法移动的回合均不能继续接受移动。

### 4.3 时间

- 使用假时钟和可控调度器，不用真实等待验证 60 秒。
- 每个计时事件携带或校验对局修订/回合身份，确保上一回合的延迟事件失效。
- 本地模式验证后台暂停时剩余时间不减少，恢复后从保存值继续。
- LAN 验证客户端显示时间不产生终局，只有主机可以提交超时结果。
- 断线宽限与回合倒计时并行运行，二者均以主机时间为准。

## 5. 持久化与兼容性

- 所有序列化测试执行“模型 → JSON → 模型”双向相等检查。
- 存档至少覆盖：协议/结构版本、棋盘、真实先手、当前方、完整移动历史、连续未吃计数、剩余时间、模式、玩家颜色和难度。
- 完成记录至少覆盖：唯一对局 ID、模式、先手、结果、终局原因、完整移动历史、实际吃子数和完成时间。
- 开发期允许显式清理不兼容旧数据；正式 1.0 后必须为每个旧版本提供迁移测试。
- 最近 20 局测试应加入第 21 局并验证只淘汰最旧记录，不影响聚合统计。

## 6. LAN 故障矩阵

| 故障 | 预期结果 |
|---|---|
| 客户端重复发送同一意图 | 主机只提交一次，统计和历史只增加一次 |
| 客户端发送旧修订意图 | 主机拒绝并提供或触发权威同步 |
| 提交消息重复到达客户端 | 客户端状态不重复变化 |
| 提交消息乱序到达 | 旧修订被忽略，修订缺口触发全量同步 |
| 客户端伪造颜色、吃子或结果 | 主机忽略声明，仅按连接身份和规则计算 |
| 客户端短暂断线后在 30 秒内恢复 | 接受全量快照，棋盘、时间和修订与主机一致 |
| 断线达到 30 秒 | 主机提交断线方负，双方不能继续落子 |
| 客户端在后台超过一个回合 | 返回后全量同步，不以本地旧倒计时判定 |
| 主机断开或退出 | 客户端进入重连等待；30 秒内恢复则全量同步，宽限到期后主机方负，不发生双端分叉 |

在线服务端还必须覆盖：同一 Socket/身份不能自我匹配或占用多局、匹配响应不泄露重连身份、旧 Socket 迟到事件被忽略、恶意 getter/超长字段不会逃逸监听器、拒绝缓存与终局房间有界回收、旧房间定时器不能删除新房间的重连记录、落库失败重试且 `matchId` 幂等、终局不变量已满足的快照不能继续落子。真实 Socket 集成测试不得替代 staging 的真实数据库、TLS、进程重启和负载验证。

## 7. Phase 4 语音与无屏验收矩阵

- 坐标层必须对全部 16 格验证 `parse(format(position)) == position`，中文一至四与 A1–D4 指向同一内部位置。
- 中心格、方向与坐标冲突、多候选识别结果必须要求重说或确认，不得直接执行。
- 假语音端口必须验证“停止监听 → 播报并等待完成 → 重新监听”，任何时刻不允许 TTS 与麦克风监听重叠。
- 权限拒绝、永久拒绝、识别/TTS 不可用、音频中断和页面销毁均要进入可预期状态，并且不影响触屏对局。
- 语音内容不得出现在普通日志、Sentry、事件/状态 `toString()`、持久化或网络请求中。
- 脚本假输入必须覆盖从开局引导、选子、落子、AI 回应、双吃、查询、暂停/恢复到终局的完整无屏流程。
- 当前自动化已经覆盖普通 PVE session 的延迟创建、存档执色、AI/后台中断、完整移动不获得 AI 权限、控制动作安全无操作和窄屏大字体；也覆盖冥想开场播报完成后才启动 60 秒时钟、AI 先手/失败重试、退出确认和播报失败不重复提交，并以假端口完成查询、重复、选子取消、暂停恢复、退出取消到 15 ply 自然终局的完整无屏对局。普通对局成功结果播报、平台权限/设置跳转和真机验收仍是未完成门禁。
- 真实引擎确定后补充 Android/iOS 权限、中文识别质量、TTS 完成时序、来电、蓝牙、音频焦点和真机无屏整局验收。

## 8. 自动化命令与门禁

Windows 本机基础验证入口：

```powershell
.\scripts\verify_release_candidate.ps1
```

该入口只使用已经安装的工具和已经解析的依赖，不执行环境或依赖安装。默认顺序执行 Dart 格式检查、Flutter analyze、普通 Flutter 单元/Widget 测试、服务端 `npm test`（其自身已包含 TypeScript/Prisma build）以及 Debug APK 构建，并将版本、commit、工作树、耗时、测试数量、APK 大小和 SHA-256 写入 `build\verification\<timestamp>\`。Debug APK 证据不替代正式签名 AAB 和商店门禁。

专用 Android API 34 冒烟会清理应用数据，默认不运行；仅在目标确认为专用 AVD 后显式启用：

```powershell
.\scripts\verify_release_candidate.ps1 -IncludeAndroidSmoke
```

需要单独补充的非默认验证：

```powershell
flutter test --no-pub --coverage
flutter test -d <dedicated-device-id> integration_test
flutter test test/integration/online_game_transport_real_server_test.dart --dart-define=RUN_ONLINE_REAL_SERVER_E2E=true --timeout 60s
```

Windows 开发机启用 `HTTP_PROXY`/`HTTPS_PROXY` 时，Flutter 测试启动器仍需直接访问本机随机回环端口。只在当前 PowerShell 进程补充回环地址后再运行测试，避免代理截断测试连接：

```powershell
$env:NO_PROXY = (@($env:NO_PROXY, 'localhost', '127.0.0.1', '::1') |
  Where-Object { $_ } |
  ForEach-Object { $_.Trim(',') }) -join ','
flutter test
```

该设置只影响当前进程，不修改系统代理。若测试文件全部在加载阶段报 `127.0.0.1` 连接关闭，应先核对回环代理绕过，再判断为代码测试失败。

规则和协议变更的合入门禁：

- 所有相关单元、BLoC、契约和集成测试通过。
- `flutter analyze` 无错误；新增警告必须处理，不能用扩大忽略规则掩盖。
- 测试启动器、网络或环境故障属于阻塞项，不能把“测试未运行”报告为通过。
- 修复规则缺陷时必须先提交可复现的失败测试。
- UI 改动附关键状态截图或录屏；LAN 改动附双端真机验证记录。
- 发布前在 Google Play 内部测试包上完成至少一次完整的离线、AI、LAN、后台恢复和进程重启验收。

## 9. 测试可维护性约束

- 棋盘场景使用统一 builder/fixture，显式列出 4×4 内容和当前行棋方，避免通过初始棋盘叠加残留棋子造成误判。
- 随机先手使用可注入、可固定的随机源；测试不得依赖概率。
- 时间测试使用假时钟；测试不得 `sleep` 60 秒。
- LAN 集成测试优先使用内存双向传输模拟重复、丢失和乱序；真机测试补充 mDNS、WebSocket 和生命周期行为。在线 Socket 层先使用假 IO 验证契约，再以本地真实 Node 双 Socket 测试和显式启用的双 Flutter `OnlineGameTransport` 测试补充传输行为；同库 outbox 先以纯仓库、worker、数据库适配器和 migration 静态契约覆盖幂等与恢复，最后在隔离 staging 验证真实 PostgreSQL migration/回滚、双 worker/慢租约、TLS、进程恢复和负载。
- 断言应同时检查结果和状态不变量：棋盘、当前方、吃子列表、未吃计数、时间、修订号、历史和统计。
- 不以覆盖率代替场景验收；关键规则分支必须有明确、可读的行为测试名称。
