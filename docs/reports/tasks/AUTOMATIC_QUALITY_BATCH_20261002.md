## 1. AI 样本与终局选择

- 原基准扩展到每个配对 20 局；先保留原黑方先手条件采集修复前后样本，再增加双先手和独立种子，三组运行合计 180 局。每回合新建 AI，落子通过真实 `GameEngine`；所有样本合法、自然终局，无搜索超时。
- 确定性战术反例先失败：困难 AI 选择 5 ply 获胜路线，局面存在 3 ply 内强制获胜路线。终局评分加入剩余深度，优先较快获胜、延迟不可避免的失败；同深度冷/热缓存继续与独立全宽搜索一致。
- 相同旧基准条件下，困难/简单从平均 27.3、最长 65 个搜索落子缩短为平均 17.8、最长 32；中等/简单仍为平均 18.1、最长 34。此比较对应旧黑方先手样本，不与新先手样本直接比较。
- `benchmark_ai.dart` 支持第二参数指定种子，输出先手、搜索 P95、完成深度分布、重复棋盘加当前方次数与终局原因。重复次数作为诊断信息，保持 50 ply 和棋规则。

独立样本命令：`dart run scripts/benchmark_ai.dart 20 20261002`。

| 配对 | 较高难度胜/负/和 | 平均 / 最长搜索落子 | 单次搜索最大耗时 |
|---|---|---|---|
| 中等 / 简单 | 20 / 0 / 0 | 17.5 / 30 | 41.915 ms |
| 困难 / 简单 | 20 / 0 / 0 | 18.6 / 54 | 149.611 ms |
| 困难 / 中等 | 9 / 8 / 3 | 32.0 / 51 | 137.454 ms |

统计不包含随机预置开局的落子；计时来自本机 Dart 运行。困难/中等仍存在重复局面与和棋；当前样本尚不足以证明困难的稳定棋力优势，继续保留多种子、战术局面与人工体验调优待办。Android 真机性能单独取样。

## 2. 自然终局与真实持久化闭环

新增 `test/integration/completed_game_lifecycle_test.dart`，6 项测试使用真实 BLoC、引擎、临时 Hive 文件和回放服务；仅音频接口替换为测试实现。

- 黑/白先手自然终局：逐手棋盘、自动存档、结果、ID、历史、统计和逐手回放一致。
- PVE 自然终局：实际人类执白、AI 先走，模式/难度及人类胜负统计正确。
- 21 局完整对局：最近 20 局正确淘汰最旧记录，聚合统计包含全部 21 局，关闭并重开 Hive 后仍可读取及回放。
- 终局记录失败一次：保留终局存档，重启后补记，保留原完成时间，同一局不重复累计。
- 已读取的真实历史记录通过历史页面进入回放，保留白方先手和最终棋盘；页面动画使用有界帧推进。

发现并修复：

1. 普通移动终局缺失 `matchId`/`startedAt`；统一通过 `GameOver.fromPlaying` 保留对局元数据。
2. 统计和历史分开写入；复用 LAN/冥想已有的 `recordCompletedGame` 原子、按 ID 去重路径。
3. 完成记录失败后存档仍被清理；先保留终局存档，成功记录后再清理。加载终局保存可重试补记，0 剩余时间仍按超时结算。
4. Hive 重开后嵌套 `Map<dynamic, dynamic>` 导致移动历史解码失败；按项目已有写法转换为字符串键 Map，兼容单吃及完整吃子列表字段。

另增加 4 项真实存储负例测试（其中包含多个变体）：未知版本、非法棋盘形状、枚举/计数/时钟边界及棋子列表与网格不一致均拒绝继续，并保留原数据。版本 1/2 现有兼容测试通过。共用棋盘解码器影响的冥想负例同时验证解码拒绝及结构合法但与历史不一致的恢复拒绝。

失败注入验证写入失败处理；设备磁盘耗尽、操作系统强杀瞬间、正式跨版本迁移继续属于独立设备/发布门禁。
