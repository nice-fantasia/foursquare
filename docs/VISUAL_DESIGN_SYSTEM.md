# 四子游戏视觉设计系统

> 状态：一期设计基线
> 一期唯一主题：现代东方棋艺（`modern_eastern`）
> 适用范围：Android 一期；后续 iOS 和新主题包沿用同一架构

## 1. 设计目标

一期视觉方向为“现代东方棋艺”，核心记忆点是：

> 一纸一局，一方朱印。

界面以温润纸张、克制墨线、玉与墨质感的棋子为主体，以朱砂色承担少量强强调。它不是复古仿制品，也不是泛化的“国风渐变”；传统材料只提供气质，信息层级、操作反馈和排版必须保持现代、清晰、克制。

设计原则：

- 棋盘是品牌核心，首页、教程、对局、回放必须使用同一套棋盘视觉语言。
- 先保证状态可辨识和操作正确，再增加纹理、光影和动效。
- 不使用蓝紫渐变、多彩模式卡片、玻璃拟态或与棋艺无关的装饰。
- 朱砂是稀缺强调色，不用于大面积背景。
- 一期仅内置并展示“现代东方棋艺”，不展示不可用的未来主题。
- 从一期开始按完整主题包设计，未来主题不应要求改动游戏规则、页面布局或状态管理代码。

## 2. 视觉语言

### 2.1 空间与材质

- 页面底层为轻微纤维感的宣纸/棉纸表面，纹理对比度必须足够低，不影响正文阅读。
- 内容层通过留白、细分隔线和轻微明度差建立层级，避免大量通用悬浮卡片。
- 棋盘可表现为置于纸面上的独立棋具，边缘具有克制的木质或铜色收边。
- 装饰元素只使用与棋局有关的墨迹、方印、细刻线；不得铺满祥云、竹叶等模板化图案。

### 2.2 色彩令牌

| 令牌 | 色值 | 用途 |
|---|---:|---|
| `paperBase` | `#F3EBDD` | 页面主背景 |
| `paperRaised` | `#FBF7EE` | 较高层内容、对话框 |
| `paperPressed` | `#E7DBC6` | 按压和选中底色 |
| `inkPrimary` | `#1F2621` | 主文字、墨方棋子 |
| `inkMuted` | `#655F54` | 次要文字、说明 |
| `jade` | `#315B4B` | 次要操作、合法落点 |
| `jadePressed` | `#24463A` | 玉色控件按压状态 |
| `cinnabar` | `#B44737` | 主操作、当前回合、告急状态 |
| `bronze` | `#917751` | 边框、最后一步、装饰刻线 |
| `divider` | `#CFC2AC` | 分隔线和弱边框 |
| `danger` | `#A9362C` | 破坏性操作和错误 |

要求：

- 正文和背景、按钮文字和按钮背景必须达到 WCAG AA 对比度。
- 胜负、错误、选中、当前回合和合法位置不能只依赖颜色表达。
- 倒计时最后 10 秒可使用朱砂色，但必须同时显示明确数字、文字或图形变化。

### 2.3 字体

字体必须随应用本地打包，不允许运行时下载。

- 展示字：使用具有楷书/文楷气质且可商用的本地字体，用于应用名、页面标题、模式名和少量关键数字。
- 正文字：使用清晰的中文无衬线字体，用于正文、规则、设置、状态说明和辅助信息。
- 候选组合可采用 LXGW WenKai Screen 与 Noto Sans SC；正式入库前必须核验具体版本许可证，并一同打包许可证文件。
- 正文不得为了视觉风格牺牲可读性；长文本、计时和操作按钮不使用书法字体。
- 字号通过语义化文本样式管理，不在页面中散落固定 `fontSize`。

建议文本层级：

| 层级 | 建议用途 |
|---|---|
| `display` | 应用名、结算印章 |
| `headline` | 页面标题、模式名称 |
| `title` | 区块标题、当前回合 |
| `body` | 正文、规则、设置项 |
| `label` | 按钮、标签、棋局辅助信息 |
| `caption` | 版本、时间、次要说明 |

## 3. 棋盘与棋子

### 3.1 棋盘

- 棋盘保持清晰的 4×4 结构，网格线使用墨色或深铜色细线。
- 背景可有极轻纸纹或木纹，但不得让网格线变得模糊。
- 外框比内部网格略重，以稳定视觉重心。
- 最后一步使用铜色起点/终点括号或角标，不在棋子上覆盖大面积高亮。
- 合法落点使用玉色圆点加短刻线；即使转换为灰阶仍能辨认。
- 选中位置使用朱砂双角框或双环，不能只改变棋子颜色。

### 3.2 棋子非颜色区分

双方棋子必须同时通过颜色、形状和内部标记区分：

- 墨方：深色实心凸面，中央具有四向刻印或明显缺口。
- 玉方：暖白/浅玉色表面，具有清晰的同心内环。
- 棋局状态区始终同时显示“墨方/玉方”文字和相应棋子图形。
- 灰阶截图中必须能够辨认双方棋子、当前选中棋子和合法落点。

### 3.3 棋盘语义

自绘棋盘只负责视觉；其上必须存在独立的 4×4 语义操作层。每个格子需要：

- 读出行、列、棋子类型和当前状态。
- 对可操作格提供“选择棋子”或“移动到此处”动作。
- 对选中、合法落点、最后一步设置明确状态描述。
- 使用稳定的语义排序，翻转棋盘时朗读顺序仍与用户看到的方向一致。
- 排除底层 `CustomPaint` 的重复语义。

示例：`第 2 行第 3 列，墨方棋子，可选择`、`第 1 行第 3 列，空位，可移动到此处`。

## 4. 动效与触觉

### 4.1 标准动效

| 场景 | 时长 | 表现 |
|---|---:|---|
| 页面进入 | 180–220ms | 淡入并上移约 12dp |
| 落子 | 320ms | `easeOutCubic` 平移，不使用弹簧反弹 |
| 吃子 | 680ms | 落子完成后先强调被吃棋子，再缩小淡出；双吃同时呈现 |
| 首手提示 | 约 420ms | 一次性朱印落章 |
| 状态切换 | 120–180ms | 明度/边框短过渡 |

不使用长期循环的装饰动画。呼吸、粒子等效果只能服务于明确状态，并在减少动态时关闭。

普通 PVP/PVE 连续落子按展示顺序播放，每手完成后保留 150ms 观察间隔；展示期间棋盘暂停接受输入，撤销、复局和退出会取消旧展示。引擎回合计时与落子记录保持原有规则。终局在棋盘展示完成后于信息区呈现结果卡片，棋盘保持可见；减少动态效果时直接呈现最终状态。

### 4.2 减少动态

有效减少动态状态为：

```text
MediaQuery.disableAnimations || 用户“减少动态效果”设置
```

开启后：

- 禁止循环呼吸、粒子、旋转和大幅位移。
- 页面和棋子状态直接切换，必要的淡入不超过 100ms。
- 不通过动画延迟操作结果或语义更新。
- 震动由独立开关控制，不与减少动态绑定。

### 4.3 触觉

- 默认开启轻震动。
- 成功选子使用轻触反馈，普通落子使用轻反馈，吃子使用一次中反馈（双吃不重复）；错误操作不触发落子反馈。触觉与动画分别遵守各自开关。
- LAN 断线、倒计时告急等状态以视觉和文字为主，不依赖震动传达。

## 5. 完整主题包接口

主题不是颜色表，而是可独立替换的完整表现包。

```text
ThemePack
├─ metadata
│  ├─ id
│  ├─ schemaVersion
│  └─ displayNameKey
├─ appTokens
│  ├─ colors
│  ├─ typography
│  ├─ spacing
│  ├─ shapes
│  └─ elevation
├─ boardSkin
│  ├─ surface
│  ├─ frame
│  ├─ grid
│  └─ moveMarkers
├─ pieceSkin
│  ├─ firstSide
│  └─ secondSide
├─ motionSpec
├─ assetManifest
└─ audioPalette
```

模块职责：

- `ThemePackRegistry`：注册主题包并按 ID 解析；一期只注册 `modern_eastern`。
- `ThemeController`：管理当前主题 ID、持久化和变更通知，不持有具体视觉常量。
- `ThemeScope`：页面和组件读取主题的唯一入口。
- `BoardSkinRenderer`：根据主题绘制底材、边框、网格和移动标记。
- `PieceSkinRenderer`：根据主题绘制或加载双方棋子，不访问 BLoC、存储、计时或网络。
- 存档只保存主题 ID 和 schemaVersion，不保存颜色、字体或资源路径。
- 主题资源必须经过 manifest 统一声明和预加载；缺失资源需要安全回退，不得导致棋局不可操作。

棋局页面只能依赖主题包公共接口，不得判断 `modern_eastern`、`rural` 等具体主题 ID。

### 5.1 一期注册策略

- 只注册并使用 `modern_eastern`。
- 设置页不显示主题切换器，可只读显示“视觉主题：现代东方棋艺”。
- 不展示“更多主题敬请期待”等不可操作入口。
- 保留主题 ID 和 schemaVersion，为后续存档迁移做准备。

### 5.2 未来乡村主题示例

未来“乡村模式”作为完整主题包提供：

- 土地/泥土背景纹理。
- 树枝在土上划出的棋盘线。
- 小石子和短树枝等可辨识棋子。
- 对应的落子、摩擦和环境音。
- 更质朴的字体、动效和页面装饰。

接入该主题时，只新增主题包、资产和许可证，不修改游戏规则、BLoC、棋局页面和网络协议。

## 6. 响应式布局

手机以竖屏为主，平板支持横竖屏自适应；一期不为桌面端单独设计。

### 6.1 断点

| 范围 | 布局策略 |
|---|---|
| `<600dp` | 手机单列；内容最大宽度 480dp；棋局操作置底 |
| `600–839dp` | 平板竖屏可使用双列模式卡片；棋局按可用高度选择堆叠或分栏 |
| `>=840dp` | 棋盘居左、状态与操作居右；整体内容最大宽度约 1200dp |

### 6.2 约束

- 棋盘尺寸必须来自父级 `LayoutBuilder` 的实际可用约束，不能直接取整机屏幕最短边。
- 不能仅通过“宽度是否大于高度”决定布局。
- 页面内容在矮屏、分屏和系统字体 200% 时必须可滚动。
- 手机横屏至少保证可完成对局、返回和查看倒计时，不要求独立的横屏视觉方案。
- 平板横屏不得把手机布局简单拉宽；首页、棋局、历史和设置应利用双栏空间。
- 所有内容尊重 Safe Area、系统导航栏和显示切口。

## 7. 无障碍验收底线

- 所有点击目标至少 48×48dp。
- 系统字体缩放至 200% 时不得截断关键文本、重叠操作或出现无法滚动区域。
- TalkBack 可独立完成选子、取消选择和落子。
- 当前回合、吃子结果、倒计时最后 10 秒、LAN 断线和重连结果使用语义 live region。
- 图标按钮必须有明确 tooltip/semantic label。
- 禁用状态同时通过外形、文字或透明度区分，不只变色。
- 棋子、图表、胜负和错误状态通过文字或形状提供冗余信息。
- 灰阶模式下仍能识别双方棋子、选中、合法落点、告急和错误。
- 减少动态开启时没有循环动画、粒子和闪烁。
- 页面焦点顺序与视觉阅读顺序一致。

## 8. 页面改造顺序

1. 主题包、字体、设计令牌、响应式断点和无障碍基础。
2. 棋盘、棋子、语义格子、落子/吃子动效。
3. 统一棋局壳层：本地 PvP、AI、计时、操作栏和结算。
4. 首页：无存档/有存档、继续游戏、一期模式入口。
5. 互动教程和规则页，复用正式棋盘组件与规则用例。
6. LAN 大厅、等待、对局、断线宽限和重连状态。
7. 最近 20 局历史、回放和统计。
8. 设置、关于、隐私与许可证。
9. 应用图标、启动屏和商店截图统一收口。

## 10. 发布前视觉门禁

- 一期只出现“现代东方棋艺”，不存在旧蓝紫主题残留。
- 首页、教程、对局、LAN、历史、回放、统计、设置和结算使用统一设计令牌。
- 棋子在彩色、灰阶和 TalkBack 下均可区分。
- C、TP、TL 和 AX 核心矩阵全部通过，无 overflow 和文字截断。
- 字体、纹理、图标、音频均有明确来源和可商用许可证记录。
- Android 应用图标、Android 12 启动屏、旧版启动屏和应用首帧视觉连续。
- 商店截图来自正式构建，不使用设计稿冒充实际界面。
